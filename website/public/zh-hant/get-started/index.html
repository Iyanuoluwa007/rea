首頁 / 快速開始

設定 REA。

將 REA 連接到你的 AI 代理，或在終端機中檢查本機應用程式。

你需要 Node.js 22（22.19 以上）、24（24.11 以上）或 26 以上版本。npm 會隨 Node.js 一起安裝。

還沒有 Node.js，或不確定是否已安裝？

開啟終端機並檢查：

終端機 
node -v
npm -v

如果 node -v 顯示 v22.19+、v24.11+ 或 v26+，就可以開始了。如果顯示較舊的版本，或出現「無法辨識」（英文系統：not recognized）或「command not found」，請安裝 Node.js 24 LTS：

Windows (PowerShell)

Windows PowerShell 
winget install OpenJS.NodeJS.LTS

如果要求你接受條款，請輸入 Y。關閉 PowerShell 後重新開啟，再執行 node -v。

如果之後執行 npx 時，PowerShell 顯示「因為這個系統上已停用指令碼執行」（英文系統："running scripts is disabled on this system"），請執行下列命令一次，然後再試：

Windows PowerShell 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

macOS

如果你使用 Homebrew：

macOS · Homebrew 
brew install node

否則：

macOS 
curl -fsSL https://fnm.vercel.app/install | bash

關閉終端機後重新開啟，然後執行：

macOS 
fnm install 24
fnm default 24

Linux

Linux 
curl -fsSL https://fnm.vercel.app/install | bash

安裝程式需要 curl 和 unzip（Debian/Ubuntu 上可執行 sudo apt install curl unzip）。關閉終端機後重新開啟，然後執行：

Linux 
fnm install 24
fnm default 24

Linux 發行版本身的 nodejs 套件通常比 22.19 舊；如果改用它，請先用 node -v 檢查版本。

想用一般的安裝程式？請從 nodejs.org 下載 LTS 版本。

連接你的 AI 代理

執行設定流程，將 REA 連接到你的 AI 代理。可選擇的用戶端包括 Claude Code、Codex、Cursor、Gemini CLI、Windsurf、Grok Build 和其他支援的 MCP 用戶端。Grok Bot 的連接器要從它的聊天介面新增。

第一次使用 AI 代理？

AI 代理是在你的電腦上運作的 AI 助理，而不是在瀏覽器分頁中。它可以讀取檔案、執行命令，並在做出變更前先詢問你。REA 為它提供逆向工程工具。

如果你還沒有 AI 代理，請挑選一個，依照它的安裝頁面安裝並登入：

  • Claude Code，由 Anthropic 開發。需要付費的 Claude 方案。
  • Codex，由 OpenAI 開發。使用你的 ChatGPT 帳號登入。
  • OpenCode，開放原始碼。可連接你選擇的模型供應商。

接著開啟它，把下面的提示詞複製進去。AI 代理會執行 REA 的設定流程，並在做任何變更前先讓你看設定計畫。

你的 AI 代理

›使用 npx rea-agents@latest setup 安裝 REA，並將它連接到這個 AI 代理。先讓我核准設定計畫，然後驗證安裝結果。

或自行執行設定
如何開啟終端機？
  • Windows：開啟「開始」功能表，輸入 PowerShell 後按 Enter。
  • macOS：按 ⌘ Space，輸入終端機或 Terminal 後按 Enter。
  • Linux：在大多數桌面環境中，按 Ctrl Alt T。

用 Ctrl V 貼上命令（macOS：⌘ V；Linux 終端機：Ctrl Shift V），然後按 Enter。

終端機 
npx rea-agents@latest setup

選擇你的用戶端並檢查設定計畫。REA 會加入它的 MCP 連線和對應的調查 skill，並備份現有的設定。套用變更前，它會先詢問你。

設定完成後，請重新啟動你的用戶端。

如何重新啟動用戶端？

桌面應用程式（Claude Desktop、Cursor、Windsurf、VS Code）：完全結束應用程式，再重新開啟。只關閉視窗是不夠的。在 macOS 上按 ⌘ Q；在 Windows 上，如果有系統匣圖示，也要從那裡結束。

終端機 AI 代理（Claude Code、Codex、Gemini CLI）：結束工作階段後重新啟動。

給你的 AI 代理一個目標路徑和一個具體的問題。如果是 JavaScript 或 Electron 應用程式，可以這樣開始：

請查看 /absolute/path/to/app，找出它如何匯出資料。列出相關的進入點、呼叫和相依性，並附上每項發現的原始碼位置。

把路徑換成你本機的目標。

如何取得資料夾的完整路徑？
  • Windows：在檔案總管中，以滑鼠右鍵按一下資料夾，然後選擇複製路徑。在 Windows 10 上，請按住 Shift 再按右鍵，然後選擇複製為路徑。
  • macOS：在 Finder 中，以右鍵按一下資料夾，按住 Option 鍵，然後選擇將「…」拷貝為路徑名稱。
  • 任何系統：把資料夾拖進終端機視窗，就會出現它的路徑。

在終端機中，如果路徑含有空格，請用引號括起來。

使用 CLI

不執行應用程式，直接分析 JavaScript 或 Electron 應用程式的資料夾或 ASAR 封存檔：

靜態應用程式分析 
npx -y rea-agents@latest analyze-javascript-application \
  /absolute/path/to/app --json

把路徑換成你解開後的應用程式目錄或 .asar 檔案。在 Windows 上，可以使用 "D:/apps/example" 這類路徑。

應用程式的 .asar 檔案在哪裡？

Electron 應用程式通常把它放在 resources 資料夾中：

  • Windows： C:\Users\<you>\AppData\Local\Programs\<App>\resources\app.asar
  • macOS： /Applications/<App>.app/Contents/Resources/app.asar （以右鍵按一下應用程式，然後選擇顯示套件內容）
  • Linux：通常在 /opt/<App>/resources/app.asar

有些應用程式會安裝在其他位置。請在應用程式的資料夾中搜尋 app.asar。

結果會識別應用程式、顯示模組之間的連結，並提供它們的原始碼位置。REA 無法解析的連結會在結果中標示出來。

如果想在 shell 中使用固定的 rea 命令：

安裝 CLI 
npm install --global rea-agents

繼續閱讀 JavaScript 應用程式指南

設定原生分析

原生二進位檔案需要本機的分析工具。請在下方選擇並設定一個工具，然後把你的執行檔或函式庫交給 REA。

選擇工具：Ghidra、Hopper 或 IDA

Ghidra

在 x64 或 arm64 的 Linux 或 macOS 上，使用現有的 Ghidra 12.1.x 安裝和 64 位元 JDK 21 或更新版本。你的 Ghidra 安裝需要適用於主機架構的原生反編譯器。執行設定前，請先設定路徑：

連接你的 Ghidra 安裝
Ghidra 連線 · macOS / Linux 
export GHIDRA_INSTALL_DIR=/absolute/path/to/ghidra_12.1.4_PUBLIC
export JAVA_HOME=/absolute/path/to/jdk-21
npx -y rea-agents@latest doctor --provider ghidra --json
npx rea-agents@latest setup

把兩個路徑換成你現有的安裝位置。設定流程會檢查它們，並為你選擇的用戶端記錄有效的設定。在 Linux arm64 上，你可能需要另外建置 Ghidra 的原生反編譯器。

在 Windows 上連接 Ghidra

Windows x64 提供實驗性的唯讀支援，可分析本機固定 NTFS 磁碟上的原生 x86 和 x64 PE 應用程式及 DLL。請使用現有的 Ghidra 12.1.x 安裝和 64 位元 JDK 21 或更新版本：

Ghidra 連線 · Windows PowerShell 
$env:GHIDRA_INSTALL_DIR = "C:/tools/ghidra_12.1.4_PUBLIC"
$env:JAVA_HOME = "C:/tools/jdk-21"
npx -y rea-agents@latest doctor --provider ghidra --json
npx rea-agents@latest setup

把兩個路徑換成你的安裝位置，然後檢查設定流程的計畫。

Hopper

在 macOS 或 Linux 上連接 Hopper。執行上面的設定命令；它會偵測現有的安裝，或提出安裝計畫讓你核准。

在 macOS 上進行無人看管的分析前，請先完成 Hopper 首次啟動時的選擇：使用示範模式，或啟用授權。

IDA

已驗證的 IDA 設定使用 Windows，搭配現有的 MCP 註冊，連接已開啟的 GUI 或無介面資料庫。Linux 和 macOS 上的無介面分析尚未驗證。

連接現有的 IDA MCP 註冊

把上游伺服器可正常運作的 command、args 和選用的 env 保存在 JSON 檔案中。也接受含有 ida-pro-mcp 項目的現有 mcpServers 物件。執行設定前，請讓 REA 指向該檔案：

IDA 連線 · Windows PowerShell 
$env:REA_IDA_MCP_CONFIG = "C:/analysis/ida-mcp.json"
$env:REA_ANALYSIS_PROVIDER = "ida"
npx -y rea-agents@latest doctor --provider ida --json
npx rea-agents@latest setup

附加模式使用上游的舊版 1.4.0 工具，且原始二進位檔案須已在 IDA 中開啟。無介面模式使用上游的資料庫監管 API，以及含有 "mode": "headless" 的註冊；實際驗證涵蓋 IDA 9.3 Windows x64 監管程式。Doctor 會檢查註冊，但不會啟動 IDA。

請把原始執行檔的路徑交給 REA，並在 CLI 查詢中加上 --provider ida。若透過 AI 代理使用，請在 REA 註冊的環境變數中加入 REA_IDA_MCP_CONFIG，並在開啟二進位檔案時選擇 IDA。

若已設定好 Ghidra，可用下列命令檢查函式：

函式分析 
npx -y rea-agents@latest function /absolute/path/to/program main \
  --provider ghidra --json

把 main 換成你要檢查的函式名稱或位址。

原生分析工作階段如何運作

每個 CLI 命令都會匯入並分析二進位檔案，然後關閉它的工作階段。在工作階段開啟期間，你的 AI 代理透過 MCP 發出的查詢會重複使用已匯入的二進位檔案。

跟著原生分析範例操作，看看函式結果如何引導出還原的計算。

取得協助

如果你的 AI 代理看不到 REA

設定完成後，請重新啟動或重新連接用戶端。用 doctor 檢查它與 REA 的連線；以 Codex 為例：

檢查單一用戶端 
npx -y rea-agents@latest doctor --client codex --json

如果提供者出現問題

檢查你正在使用的提供者。以 Ghidra 為例：

檢查單一提供者 
npx -y rea-agents@latest doctor --provider ghidra --json

報告會列出失敗的檢查項目和建議的下一步。

  • REA 常見問題關於更新、AI 代理和分析的簡短解答。
  • 選擇調查指南二進位檔案、Electron 應用程式和瀏覽器的實作範例。
  • GitHub issues回報問題時，請附上命令和診斷結果。
  • REA 社群問題、調查和進行中的工作。
